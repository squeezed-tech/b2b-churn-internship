# Журнал недели 3 — Признаки и baseline модели

## Честная валидация (главная правка после ревью)

### Проблема: AUC 0.946 — слишком хорошо
В первой версии не было зазора между окном наблюдения и окном прогноза.
Коллапс выручки (начинается за 4-5 месяцев до ухода — см. event study недели 1)
попадал прямо в признаки, и модель не предсказывала будущее, а читала настоящее.

### Решение: зазор в 2 месяца
Теперь:
- Наблюдение: OBSERVATION_MONTHS месяцев по месяц снапшота включительно → признаки
- Зазор: GAP_MONTHS = 2 месяца после снапшота → не используются вообще
- Прогноз: FORECAST_MONTHS месяцев после зазора → только таргет

Пример для снапшота 2025-06:
- Наблюдение: 2025-01…2025-06 (признаки)
- Зазор: 2025-07, 2025-08 (модель не видит)
- Прогноз: 2025-09…2025-11 (таргет)

### Проблема: пересечение train/test
Старое разбиение: train = 2024-07, 2024-10, 2025-01; test = 2025-04, 2025-07, 2025-10.
Снапшот 2025-01 из train прогнозировал 2025-02…04, а снапшот 2025-07 из test
наблюдал 2025-02…07. Общие месяцы → тест не независимый.

### Решение: выкинуть пересечения
Новое разбиение:
- train: 2024-07, 2024-10 (прогноз кончается на 2025-03)
- val: 2025-01 (для early stopping CatBoost)
- test: 2025-10 (наблюдение начинается с 2025-05)

Пересечения нет: 2025-03 < 2025-05.

### Фильтр короткой истории
Добавлен MIN_OBS_MONTHS = 4: клиент должен иметь минимум 4 месяца в окне
наблюдения, иначе "среднее за 6 месяцев" считается по 1-2 месяцам.
Датасет уменьшился на ~16k строк (было 214k, стало 198k).

## Результат

После правок метрики упали до честного диапазона:
- Правило: AUC 0.793, Lift 5.66x
- Логрег: AUC 0.827, Lift 6.03x
- CatBoost: AUC 0.843, Lift 6.48x

Бизнес-вывод: в топ-10% клиентов по риску попадает 65% всех будущих уходов,
lift = 6.5x. Это значит, что если бизнес будет работать только с топ-10%
клиентов по прогнозу риска, он охватит 65% всех реальных уходов — в 6.5 раз
эффективнее случайного выбора.
