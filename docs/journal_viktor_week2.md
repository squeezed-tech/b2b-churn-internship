# Журнал недели 2 — сборка обучающей выборки

## Определение таргета
- **Объект наблюдения:** клиент (`client_id`) в точке отсчёта (snapshot — месяц `YYYY-MM`).
  Одна строка выборки = один клиент в одном snapshot.
- **Окно наблюдения:** 6 месяцев, включая месяц снапшота
  (для snapshot `2025-06`: `2025-01`…`2025-06`). Признаки — строго из этого окна.
- **Окно прогноза:** 3 месяца после месяца снапшота
  (для `2025-06`: `2025-07`…`2025-09`). Таргет — строго из этого окна.
- **Событие оттока (target = 1):** в окне прогноза выполнилось хотя бы одно:
  1) явный отток: `termination_date` попал в окно прогноза;
  2) тихий отток: суммарный `revenue` за 3 месяца окна = 0
     (перестал пользоваться услугами, не расторгая договор).
  Иначе target = 0.
- **Фильтр "мёртвых душ":** в выборку попадают только клиенты, которые
  подключились до снапшота, не расторгнуты до снапшота и имели `revenue > 0`
  в месяц снапшота.

## Защита от data leakage
- `current_status` не используется ни как признак, ни для таргета: это статус
  на конец июня 2026, то есть информация из будущего для любого исторического
  snapshot.
- `termination_date` используется только для построения таргета из окна
  прогноза и никогда — как признак.
- Полный список признаков с пометками "точно не из будущего" — в ноутбуке
  `02_dataset.ipynb`, секция "Самопроверка на утечку".

## Наблюдения и гипотезы
- Доля оттока плавно растёт: 2.9% (2024-07) → 5.3% (2025-10). Похоже на тренд,
  а не на шум — проверить на неделе 3 (возможно, скрытый паттерн данных).
- База живых клиентов растёт: 31.9k → 38.8k — подключения обгоняют отток.
